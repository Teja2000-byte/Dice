Domain / Role: Front-end software developer supporting inventory-data quality.

Goal: Build the missing business validation for a synthetic, offline inventory-import review tool. In Visual Studio Code, preserve a starter HTML page and requirements brief, normalize item IDs, reject missing values, duplicate IDs and invalid quantities, and clear stale preview rows before each review. Keep the entire batch out of the preview if any row fails, and retain the starter's safe text rendering and local-review-only wording. In Firefox, demonstrate the incomplete baseline, then verify the completed page against twelve acceptance groups, including recovery after an error and literal display of markup-like text. Deliver one standalone HTML file with no network or storage calls.

Starting materials: Two synthetic local files will be prepared with Gemini before recording. input 1.html will be a self-contained visual starter with a labeled pipe-delimited text area, Review import button, live status, error list and preview table. Its existing parser will check the header and field count, preserve source line numbers, trim values and ignore blank lines. Its renderer will already use textContent for safe cell display. A validateBatch(records) function will initially return an empty error list, leaving business validation and ID normalization unimplemented; the review handler will also leave old preview rows visible after a later rejection. input 2.md will define the business rules and twelve acceptance groups. Neither input will contain private information, external assets or network/storage calls. Both inputs will remain unchanged, and the completed output will be created during recording.

Steps (with the apps for each):
1. In Visual Studio Code, read the requirements, inspect the parser, validation stub, renderer and review handler, and use Save As to create final output 1.html while preserving the inputs.
2. In Firefox, establish the incomplete baseline: a duplicate-ID batch is incorrectly accepted, and a later bad-header rejection leaves that earlier preview visible.
3. In Visual Studio Code, implement case-insensitive ID normalization and duplicate detection, required ID/location checks and digit-only integer quantities from 0 to 9999 inclusive. Clear the preview at the start of every review, preserve the safe renderer and local-only messages, and save the separate final file.
4. In Firefox, run the twelve acceptance groups. Verify canonical IDs, normalized quantities, totals, source-line errors, all-or-nothing rejection, literal markup-like text, and valid-invalid-valid recovery without stale or duplicate preview rows. Return to Visual Studio Code to inspect the saved deliverable, correcting and retesting any observed problem.

Deliverable: final output 1.html, one standalone local inventory-import review tool. It previews normalized records only when the complete batch passes, reports row-specific failures, and does not imply that inventory was imported or saved. The recording shows requirement-based engineering decisions, an observed baseline, implementation, verification and final saved-file inspection. The two original inputs remain unchanged.
